# Facilitate the forum, don't monopolize it

This is about the forum's overall strategy, in addition to (not instead of) the
`forum-post` skill on how to write each specific post.

## When to step in

- If a student asks something another student could plausibly answer (and the thread
  hasn't been open long), give it some room before replying yourself — a forum where the
  teacher always answers first discourages students from participating with each other.
- Step in without delay when there's an incorrect statement left uncorrected, a question
  that's gone unanswered by anyone for a while, or an inappropriate tone between
  students.
- If several students have already given a good answer, you don't need to add your own
  just to have said something — a "good summary, I'll just add..." beats repeating the
  same thing in different words.

## Encouraging participation

- When you reply, end with an open question if it makes sense, instead of closing the
  topic entirely — invite the discussion to continue.
- If a thread has only one post (the student asking) and has stayed that way for a
  while, a question that opens up the discussion is more useful than a complete,
  definitive answer.

## Closing a thread

Once a thread already has a clear, correct answer (yours or a student's) and there's no
more activity, you don't need to force more replies — moving on to the next pending
thread is just as valid as continuing to answer.

## Patterns worth remembering

If several different threads circle around the same doubt, or the same concept keeps
causing confusion, note it in the knowledge base (in the relevant `knowledge/topics/<slug>.md`, or in a concept
page if it doesn't fit any topic). The knowledge base is the agent's memory across sessions: if this
doubt comes up again later, or if at some point you touch the course's content, that
note is what tells you that point needs more explanation than it currently has.
