# Internationalize teacher-agent's own texts

## Goal

Show every text teacher-agent writes for a person (CLI help and messages, the setup wizard, the session's header, welcome and closing, tool labels, the publish gate's panel) in the same language as agent-kit's texts: Spanish, English, French or German.

## Context

- Since 0.11, agent-kit's texts (status bar, panels, shortcuts, its own tool labels) follow one language per process: `--language=<code>`, then the agent's option, then the system's (its ADR-019). teacher-agent passes `agent.language` as that option (`interfaceLanguage()`).
- teacher-agent's own texts don't follow it, and aren't even consistent:
  - the CLI, the wizard, the session's messages and the gate's panel are fixed in Spanish;
  - the browser tool labels (`src/toolLabels.ts`) are in English.

  A chat mixes the kit's Spanish ("Pidiendo aprobación humana") with teacher-agent's English ("Navigating to …", "Clicking …").
- Text for the model stays in English (prompts, skills, tool descriptions, hook deny reasons), as in the kit's ADR-019: the model follows English instructions best. What the agent publishes in Moodle keeps following the course's language (`language.md`).
- The agent's own narration drifts into English ("Posted successfully…"). agent-kit's reply-language line, turned off in 0.6.0 (`replyInLanguage: false`), is what keeps it in the chosen language. It's compatible with `language.md`: the line is about replies, and the prompt still says to publish in the course's language.

## Changes

- `src/messages/`: `en.ts` (the reference and the `Messages` type), `es.ts`, `fr.ts` and `de.ts`, each typed as `Messages` so a missing key fails typecheck. A `t()` reads agent-kit's `getLanguage()`, so both always agree.
- The language is resolved once, at the CLI's start, with agent-kit's `detectLanguage()`:
  - `--language`, then the workspace's `agent.language`, then the global `defaultLanguage`, then the system's;
  - set with `setLanguage()` before the help or the wizard print anything;
  - `interfaceLanguage()` returns nothing for a language it doesn't know (the system's then wins), instead of Spanish.
- Every person-facing text goes through `t()`:
  - `cli.ts`: help, errors, the skills/commands catalog;
  - `menu.ts`: the wizard, the mode and run-kind prompts, the practice-runner question;
  - `agent.ts`: header fields, welcome, prompt label, the plain heading, interruption and closing messages, errors;
  - `workspace.ts`: errors, the default label;
  - `toolLabels.ts`: every `browser_*` label;
  - `publishGate.ts`: the panel.
- Tool labels in a quieter color (issue #5, `tool-lines-color`): `friendlyToolLabel` returns them dimmed.
- `replyInLanguage` back on, so the agent narrates in the chosen language.
- README/CHEATSHEET: `--language` and what it changes.

## Acceptance

- `teacher-agent --help`, `init` and a chat show teacher-agent's texts in the kit's language with `--language=es`, `en`, `fr` and `de`, and with `agent.language` in the workspace. Nothing is left in another language, except the model's own words and Moodle's page names.
- A chat against the sandbox in Spanish shows tool lines in Spanish and dimmed, and the agent narrates in Spanish.
- `verify` passes, with typecheck guarding the catalogs.
